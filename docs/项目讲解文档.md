# 课程报告智能助教 (Voice-TA) — 完整项目解析

## 一、项目概览

**Voice-TA** 是一个面向高校教学的 **AI 语音问答助教系统**。核心场景是：学生上传课程报告 → 系统自动分析并生成提问计划 → AI 通过实时语音对学生进行追问式问答 → 自动生成总结报告供教师查看。

默认账号：

- 管理员：`admin / admin123`
- 教师：`teacher / teacher123`
- 学生：`student / student123`

### 2. 课程管理

| 角色 | 功能 |
|------|------|
| 教师 | 创建课程、设定作业名称和作业要求 |
| 学生 | 通过课程码加入课程、查看已加入的课程列表 |
| 系统 | 统计每门课程的提交数、学生数、已分析数、已总结数 |

### 3. 报告上传与智能分析

这是系统的核心功能之一，完整流程如下：

```
学生上传 PDF/Word/Markdown/TXT
        ↓
系统保存文件到 data/uploads/
        ↓
后台异步调用 DashScope API（qwen-long 模型）
  ├─ 上传文件到 DashScope File API
  ├─ 使用 fileid:// 协议让模型读取文件内容
  └─ 要求模型输出结构化 JSON
        ↓
生成分析结果（存入 reports.result 字段）：
  ├─ report_brief: 报告摘要（主题、核心结论、方法）
  ├─ question_plan: 结构化问题计划（含优先级、追问策略）
  ├─ voice_qa_prompt: 语音问答 system prompt
  ├─ teacher_attention: 教师关注点
  └─ coverage_threshold: 问答结束条件
```

**Prompt 设计亮点**（`backend/app/services/prompt_templates.py`）：

- 明确要求模型输出严格 JSON（`response_format={"type": "json_object"}`）
- 问题按 `high / medium / low` 三级优先级分类
- 每个问题都带 `sufficient_answer_criteria`（充分回答标准）和 `follow_up_when_insufficient`（追问策略）
- 自动生成可直接注入语音模型的 `voice_qa_prompt`

### 4. 实时语音问答

这是系统最核心也最复杂的功能，涉及三层通信架构：

```
浏览器 (学生)                    FastAPI 后端                  火山引擎
    │                               │                            │
    │─── WebSocket 连接 ──────────► │                            │
    │                               │─── WebSocket 连接 ────────► │
    │                               │    (二进制协议)              │
    │                               │                            │
    │◄── ready (采样率/格式) ────── │◄── StartConnection ──────── │
    │                               │◄── StartSession ─────────── │
    │                               │─── chat_text_query(开场) ─► │
    │                               │                            │
    │─── 浏览器麦克风 PCM ────────► │─── gzip(audio) ───────────► │
    │                               │◄── TTS PCM 音频 ─────────── │
    │◄── PCM 音频播放 ───────────── │                            │
    │                               │◄── 转写文本事件 ─────────── │
    │◄── model_text / user_text ── │                            │
    │                               │                            │
    │─── finish ──────────────────► │─── FinishSession ─────────► │
    │◄── done (QA记录) ──────────── │─── 保存 qa_records ──────── │
```

**关键实现细节**：

1. **浏览器端**（`frontend/src/app/student/VoiceQAConsole.tsx`）：
   - 使用 `getUserMedia` 获取麦克风音频
   - `ScriptProcessorNode` 实时采集 PCM 数据
   - `floatTo16kPcm()` 将浏览器采样率降采样到 16kHz 16-bit PCM
   - `playPcmFloat32()` 播放服务端返回的 24kHz float32 PCM 音频
   - 时间轴连续播放（`playbackTimeRef`）避免音频间隙

2. **后端中转**（`backend/app/main.py` 第 379-490 行）：
   - FastAPI WebSocket 端点 `/api/sessions/{session_id}/voice-qa`
   - 双向异步数据转发：`browser_to_dialog()` + `dialog_to_browser()`
   - `DialogTranscript` 实时解析对话轮次，提取 Q&A 对

3. **火山引擎协议**（`backend/app/services/realtime_dialog.py`）：
   - 自定义二进制协议（4字节 header + gzip payload）
   - 事件码：450（用户开始说话）、459（用户说完）、359（TTS 播放完）
   - `is_dialog_done()` 检测固定结束语 "好的，我的问题问完了" 触发结束

### 5. 问答总结生成

语音问答结束后，调用 `POST /api/sessions/{session_id}/voice-qa-summary`：

- 将报告原文 + 分析结果 + Q&A 记录一起提交给 DashScope
- 生成面向教师的中文总结报告
- 包含：报告核心内容、学生问答表现、已回答清楚的点、仍需追问的点、评分建议

### 6. 系统配置

管理员可在 `/config` 页面配置：

- **DashScope**：API Key、Base URL、文本模型（默认 `qwen-long`）
- **火山引擎实时语音**：App ID、Access Token、Secret Key
- 配置保存在 `data/config.json`（已 `.gitignore`）

## 三、核心原理解析

### 3.1 文档分析原理

系统使用 **阿里云 DashScope** 的文件理解能力：

```python
# 上传文件到 DashScope
file_object = client.files.create(file=file_handle, purpose="file-extract")

# 使用 fileid:// 协议让模型直接读取文件
messages = [
    {"role": "system", "content": f"fileid://{file_object.id}"},
    {"role": "user", "content": prompt},  # 结构化分析 prompt
]
completion = client.chat.completions.create(
    model="qwen-long",
    messages=messages,
    response_format={"type": "json_object"},  # 强制 JSON 输出
)
```

`qwen-long` 模型支持超长上下文，能完整"阅读"整篇报告，然后按 Prompt 要求输出结构化分析。

### 3.2 实时语音对话原理

系统使用 **字节跳动火山引擎** 的端到端实时语音对话服务：

1. **二进制协议**：自定义 4 字节 header（版本号、消息类型、序列化方式、压缩方式）+ gzip 压缩的 payload
2. **连接流程**：`StartConnection(事件1)` → `StartSession(事件100)` → `ChatTextQuery(事件501)` → 音频流 `SendAudio(事件200)` → `FinishSession(事件102)` → `FinishConnection(事件2)`
3. **双工通信**：学生麦克风音频上行 → 服务端 ASR+推理+TTS → 音频下行，同时返回转写文本
4. **结束检测**：模型在判断问题问完后会说出固定结束语 "好的，我的问题问完了"，后端通过 `is_dialog_done()` 检测此短语触发结束

### 3.3 System Prompt 注入策略

语音问答阶段不直接把整份报告塞入上下文，而是注入精炼的提问策略：

```python
# 从分析结果中提取 voice_qa_prompt + question_plan
system_prompt = build_realtime_system_prompt(
    str(result.get("voice_qa_prompt") or ""),
    result.get("question_plan") or [],
)
```

这遵循了设计文档中描述的 **"每轮小上下文注入"** 原则——用结构化状态替代全文回放，控制延迟和 token 消耗。

### 3.4 数据库设计

4 张核心表 + 1 张关联表：

| 表 | 用途 |
|----|------|
| `users` | 用户（id=SHA256(username), password_hash=SHA256(password)） |
| `courses` | 课程（含作业名称、作业要求） |
| `course_enrollments` | 学生-课程关联 |
| `reports` | 报告会话（含文件路径、状态、分析结果 JSON） |
| `qa_records` | 问答记录（外键关联 reports 和 users） |

### 3.5 密码安全

密码使用 **SHA-256 哈希** 存储在 `password_hash` 字段。用户 ID 也是 `SHA256(username)` 的派生值。

## 四、使用讲解（快速上手）

### 前提条件

- Python 3.10+（推荐 Conda 环境）
- Node.js 18+
- MySQL 8.0 服务已启动（默认 `root/root`）
- 阿里云 DashScope API Key
- 火山引擎实时语音对话服务凭证

### 步骤 1：安装依赖

```bash
# 创建并激活 Conda 环境
conda create -n voiceTA python=3.10 -y
conda activate voiceTA

# 安装 Python 依赖
pip install -r requirements.txt

# 安装前端依赖
cd frontend
npm install
cd ..
```

### 步骤 2：确认 MySQL 配置

确保 MySQL 运行在 `127.0.0.1:3306`，用户 `root`，密码 `root`。后端启动时会自动创建 `voiceTA` 数据库和所有表。

如需修改，设置环境变量：

```powershell
$env:VOICE_TA_DATABASE_URL="mysql+pymysql://root:yourpassword@127.0.0.1:3306/voiceTA?charset=utf8mb4"
$env:VOICE_TA_DB_PASSWORD="yourpassword"
```

### 步骤 3：启动服务

```bash
# 一键启动（前后端同时启动）
conda activate voiceTA
python scripts/run_dev.py
```

或分别启动：

```bash
# 终端 1：后端
conda activate voiceTA
python -m uvicorn backend.app.main:app --reload --host 127.0.0.1 --port 8000

# 终端 2：前端
cd frontend
$env:NEXT_PUBLIC_API_BASE_URL="http://127.0.0.1:8000"
npm run dev
```

### 步骤 4：配置系统

1. 访问 `http://localhost:3000/config`
2. 填写 DashScope API Key
3. 填写火山引擎实时语音 App ID、Access Token、Secret Key
4. 点击保存

### 步骤 5：教师创建课程

1. 用 `teacher / teacher123` 登录
2. 进入教师端，创建课程（如 "推荐系统"）
3. 填写作业名称和作业要求

### 步骤 6：学生提交报告

1. 用 `student / student123` 登录
2. 进入学生端，选择课程并上传报告文件（PDF/Word/MD/TXT）
3. 等待系统分析完成（状态从 `pending` → `processing` → `completed`）

### 步骤 7：语音问答

1. 分析完成后，点击 "开始实时语音问答"
2. 浏览器会请求麦克风权限
3. AI 助教将按优先级逐题提问，学生语音回答
4. 问答结束后系统自动生成总结

### 步骤 8：教师查看

1. 教师端可查看所有学生的报告分析、Q&A 记录和总结

### 独立命令行 Demo

```bash
# 修改 single_file_realtime_dialog.py 中的 API_APP_ID 和 API_ACCESS_KEY
python single_file_realtime_dialog.py
```

这个独立脚本直接使用 PyAudio 采集麦克风音频，通过火山引擎 API 进行实时对话，不需要前端和 MySQL。

## 五、后续需要完善的地方

### 🔴 高优先级（核心体验）

| 问题 | 说明 | 建议 |
|------|------|------|
| **密码安全** | 使用 SHA-256 单次哈希，无盐值，易被彩虹表攻击 | 改用 `bcrypt` 或 `argon2` 加盐哈希 |
| **无 JWT/Session** | 前端仅用 localStorage 存用户信息，无 token 验证 | 实现 JWT 认证 + 后端中间件校验 |
| **无权限校验** | API 端点无鉴权，任何人都可调用所有接口 | 添加基于角色的 API 权限中间件 |
| **文件存储** | 文件存本地 `data/uploads/`，无加密 | 接入对象存储（S3/TOS），敏感文件加密 |
| **异步任务** | 使用 FastAPI `BackgroundTasks`，重启后任务丢失 | 改用 Celery + Redis 消息队列，支持重试和持久化 |

### 🟡 中优先级（功能完善）

| 问题 | 说明 | 建议 |
|------|------|------|
| **问答中断恢复** | 语音问答中途断开无法恢复 | 增加断线重连 + 会话状态持久化 |
| **文本降级** | 语音失败后无备选方案 | 实现文本问答模式作为降级方案 |
| **前端状态管理** | 无全局状态管理，数据获取分散 | 引入 TanStack Query / Zustand |
| **实时通知** | 分析完成后需手动刷新 | WebSocket/SSE 推送分析完成通知 |
| **版本迭代** | 设计文档中提到的"学生修改意见 → 新版本总结"未实现 | 实现总结报告版本管理和修订功能 |
| **大文件上传** | 无分片/断点续传 | 接入 tus 协议或对象存储 SDK |

### 🟢 低优先级（优化增强）

| 问题 | 说明 | 建议 |
|------|------|------|
| **数据库** | MySQL → 设计文档推荐 PostgreSQL + pgvector | 迁移到 PostgreSQL 以支持向量检索 |
| **文档解析** | 直接依赖 DashScope File API | 增加本地解析层（unstructured / pdfplumber）用于预处理 |
| **监控** | 无分析成功率、延迟等指标监控 | 添加 Prometheus + Grafana 监控 |
| **审计日志** | 无操作审计 | 增加统一的审计日志中间件 |
| **测试** | 无单元测试/集成测试 | 补充 pytest + Vitest 测试用例 |
| **容器化** | 无 Docker 支持 | 添加 Dockerfile + docker-compose.yml |
| **国际化** | 全中文硬编码 | 抽取 i18n 资源文件 |

### 🔵 架构层面（设计文档愿景 vs 现状差距）

对照 `docs/课程报告助教-设计文档.md`，以下架构愿景尚未实现：

1. **向量检索层**：设计文档提到用 `pgvector / Milvus` 做课程要求和历史案例的语义召回，当前完全依赖 LLM 的长上下文能力
2. **Agent 编排决策器**：设计文档提出 "Continue / Clarify / Next / Done" 四类动作的规则引擎，当前由语音模型自主判断
3. **多轮追问质量控制**：设计文档要求 "规则引擎 + 小模型评分 + 语音模型复核" 的组合策略，当前仅靠 prompt 控制
4. **案例与问题模板库**：设计文档提到需要积累历史案例和高质量问法模板，当前每次分析都是无记忆的独立任务

## 七、总结

Voice-TA 是一个 **教学场景下的 AI Agent 系统**，已成功跑通了从"报告上传 → 智能分析 → 实时语音追问 → 总结生成"的完整主流程。项目在技术栈选型上比较合理（FastAPI + Next.js + DashScope + 火山引擎），代码组织清晰。当前版本定位为 **MVP/原型阶段**，核心语音交互链路已通，但在安全性、可靠性、可扩展性方面还有较多提升空间，适合作为后续深入开发的基座。
