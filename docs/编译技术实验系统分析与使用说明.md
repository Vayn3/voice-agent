# 编译技术实验：系统分析、实现与使用

## 当前系统与改动依据

系统采用 Next.js 16 + React 前端、FastAPI 后端、SQLAlchemy/PyMySQL + MySQL 持久化。`backend/app/main.py` 提供登录、课程、选课、提交、分析状态、问答记录、实时语音 WebSocket 和总结接口；`store.py` 负责课程、报告及问答的数据库操作。`database.py` 在启动时建库、建表、补充兼容字段和默认用户。`config_store.py` 将两家模型服务的密钥保存到被 Git 忽略的 `data/config.json`。

原流程是单份报告上传 → DashScope Files `file-extract` → `qwen-long` 输出 JSON 提问计划 → 豆包实时语音 → 保存问题与回答 → 文本总结。浏览器将麦克风音频转为16kHz PCM，经后端转发火山实时语音；返回24kHz音频在浏览器播放，也可转发ROS扬声器。识别到“好的，我的问题问完了”结束问答，前端调用总结接口。ROS不是本机Web功能的必要依赖。

原实现对本次任务的不足：

- 前后端只接收单份PDF、DOC、DOCX、MD、TXT，不能直接接收C/C++、Flex/Bison文件或完整项目。
- 课程只保存一段要求，没有阶段与任务ID、必做/选做区分及结构化评价。
- 同一学生重交时删除旧报告和问答，阶段记录不能长期保留。
- 分析主要概括报告，没有逐任务实现细节、源码行号、缺失证据和粗略完成度。
- 非JSON模型输出被直接当成语音提示词，异常可能伪装为成功。
- 实时语音结束条件只看优先级，学习、AI体验、课程感受和建议没有强制覆盖。
- 最终总结只有文本，未形成可核查的分项评分或实际问答覆盖检查。
- 本机课程在MySQL中，Git拉取代码不会复制数据库内容。

本次已针对这些问题实现课程种子、阶段任务、联合材料分析、历史保留、必答问题和结构化评分。

## 任务书的完整范围

原件为 `docs/《编译技术》实验任务书(软件2026).doc`。已通过本机Word以只读方式提取正文，完整转录保存为 `docs/compiler-taskbook-transcription.txt`。文件名标注软件2026，正文写的是“2024级 软件学院软件工程专业”，保持原文，不将其改写为2026级。

课程名：**编译技术实验**；任课教师：**胡雯蔷**；固定课程码：**COMP2026**。作业名为“编译技术实验与完整编译器课程设计”。课程界面可以展开各阶段任务，或阅读完整任务书与本系统补充要求。

| 阶段 | 必需内容 | 重点核查 |
| --- | --- | --- |
| 实验1 | Flex `lex.l`生成词法分析器；另外手工C/C++自动机；单词二元组与错误字符信息 | 规则优先级、最长匹配、状态/转移/终态及错误处理；Flex产物不能代替手工自动机 |
| 实验2 | `lex.l`、`parser.y`、`displayAST.c`，可用`def.h`共享类型 | token与语义值、文法/优先级、语义动作、AST构造与可视化 |
| 实验3 | 遍历AST，单作用域符号表与解释执行，变量名/类型/值 | 首次赋值新增、再赋值更新；输入类型识别；混合运算浮点转换；`3/2=1`、`3.0/2=1.500000`；未定义变量报错 |
| 课设阶段一 | 自定义语言与文法、词法/语法分析；char/int/float；算术/比较/自增自减/复合赋值；if/while/break/continue/for；多维数组、两种注释 | 文法完整性、工具与自身工作、AST显示开关；不要求预处理或多文件 |
| 课设阶段二 | 自行设计管理符号表，动态显示与开关，属性计算，静态语义检查 | 不同错误类别、检测代码、独立触发样例；工具不免除符号表管理要求 |
| 课设阶段三 | 定义并生成IR、可控制显示 | 表达式、控制流、数组与IR衔接；基本块、DAG优化属于选做 |
| 课设阶段四 | 寄存器分配、目标代码生成和运行证据 | IR到目标指令、资源不足处理；MIPS/QTSPIM/MARS是建议；LLVM允许；仅支持整型等限制须在报告说明 |

任务书原文是“最低要求15种以上”的静态语义错误，按不少于15种核查，不能擅自增加第16种硬性要求；原文没有指定固定错误清单，不能编造官方错误类别。平台的其他说明、测试样例、报告统一封面/目录模板均未包含在本文件中，必须由学生提供，不能假称已掌握其内容。

字符串、结构、switch、中间代码优化为选做，缺失不降低必做完成度。扩展与特殊内容需告知教师并详述。任务书允许AI和其他工具辅助，最终功能仍须满足要求。

完整交付还包括文献阅读、技术路线和方案、标准格式报告打印版、源程序、目标程序或解释器、测试文件和电子报告。基础实验需在头歌通关，课设在作业目录提交；现场检查至少完成中间代码后可申请。本系统的提交与答辩补充课堂评价，不改变头歌提交要求。

## 文件与模型分析

阿里云[Qwen-Long官方说明](https://www.alibabacloud.com/help/en/model-studio/long-context-qwen-long)将其定位为长文档处理，文件格式列表包含TXT、DOCX、PDF等，没有C、Flex `.l`、Bison `.y`或ZIP。[Files官方接口](https://www.alibabacloud.com/help/en/model-studio/openai-file-interface)说明file-id用于Qwen-Long/Qwen-Doc-Turbo；不能把任意代码模型直接换到原来的file-id调用中。[Qwen-Coder官方说明](https://help.aliyun.com/en/model-studio/qwen-coder)说明其面向代码任务，同时建议考虑新的通用模型。

因此：`qwen-long`可以阅读以文本提供的源码并做初步解释，但其长文档能力不足以证明能可靠完成编译器实现审查；格式接收能力与代码推理能力是两个问题。系统保留qwen-long读取PDF/DOCX，新增独立的代码审查模型配置，默认`qwen3-coder-plus`（本机实际调用已通过），也允许填写账号可用的通用模型。此默认值是经当前环境验证的可用选择，不是所有模型上的最优质量结论。更换模型后应使用验收脚本复测。

处理流程：

1. 接收多文件或ZIP。支持C/C++/头文件、`.l/.lex`、`.y/.yacc`、ANTLR `.g4`、Java、Python、LLVM `.ll`、汇编、构建/测试文本、PDF/Word等；Makefile等无扩展名文本也允许。保留原文件名、目录、字节数和SHA256。
2. UTF-8/GB18030/带BOM的UTF-16源码本地读取，保留内容，不删除注释、不筛选首尾；按行号和24,000字符块完整传入代码审查模型。超长单行也分段读完。
3. PDF/DOCX完整传给文档模型做文件审查；旧DOC通过本机Word/LibreOffice/antiword转换成文本后全量分块。本机已验证能读取任务书DOC。其他电脑若缺少转换器，界面明确提示另存DOCX/PDF，不能把二进制DOC伪装成文本。
4. 每文件/每块提取任务对应的实现、证据、测试、缺陷、依赖及不确定点，再用全部审查记录进行跨文件联合分析。跨块未见功能不能立即认定整个项目缺失。
5. 按所选范围校验所有阶段、所有任务和每阶段必答问题。缺阶段、缺任务、无证据却声称满足、非法JSON或输出截断均进行一次修复；仍失败则标记分析失败，不注入异常内容到语音模型。
6. 输出阶段满足程度、任务实现细节/证据/优缺点/待核实问题、粗略完成度、文件覆盖清单及主持提示词。必做分单独计算，选做单列。

上传限制为30个入口文件，展开后200个文件；单文件20MiB、展开总量40MiB、可读源码/文本120万字符；联合审查记录最多18万字符。超限要求按阶段拆分，不截断后宣称完整分析。ZIP拒绝路径穿越、符号链接、加密文件、依赖/Git目录；二进制目标程序和嵌套压缩包在清单中记录为排除项，不能冒充代码证据。系统不会执行学生程序。文档供应商的解析可能遗漏图片/公式/扫描内容，文件完整提交不等于解析无误或运行成功，结论需说明证据边界。

## 语音核查与最终评分

主持计划按当前阶段实际源码和报告提出实现问题，核查设计依据、具体输入输出、类型/错误/控制流、测试和边界处理，针对缺陷或报告与源码冲突追问；一次一个问题，回答不足最多追问两次。

系统保证计划中包含学习收获、AI交互体验、课程感受和课程建议四类必答问题，并使用明确的标准问题文本避免模型只问“有没有用AI”。未用AI则问独立解决过程，不预设使用AI或作弊。最终评价看学生能否解释自己的设计、回答与证据是否一致，不把AI使用、口音、性格或负面课程意见作为扣分依据。

补充分值（任务书没有原定权重）：

| 分项 | 权重 | 依据 |
| --- | --- | --- |
| 作业质量 | 60% | 必做满足度、源码实现、测试与报告证据，口述新证据可调整但必须解释 |
| 实现理解与答辩 | 30% | 具体设计、代码路径、输入输出、故障和边界，避免只背概念 |
| 学习反思 | 10% | 学习/AI经历/课程反馈的具体程度，意见方向不影响得分 |

模型输出0–100分项分和依据，服务端验证范围并计算`0.6×作业 + 0.3×答辩 + 0.1×反思`，保存最终建议分、熟悉度、优缺点和改进建议。每个必答问题要引用实际存在、非空的问题与回答记录；同一个回答不能代替全部必答问题。缺必答覆盖时保留总结，`final_score=null`并提示补充问答。语音端仍由模型主持，实际覆盖由总结审查与引用校验共同核实，不假称能绝对保证模型每轮遵守。

阶段提交只对该阶段评分；选“全部实验与课设阶段”且联合提供所有材料后形成综合评分，系统不会把某一阶段成绩显示为整门课最终成绩。所有分数是教师复核的建议，本次验收使用模拟回答，未对真实学生生成成绩。

## 数据库与Git迁移

`courses.assignment_spec`保存阶段、任务、选做、口头核查点和评分来源；`reports.stage_id/submission_files/assignment_spec`保存提交阶段、文件清单和当时要求快照；既有报告字段、课程和问答兼容保留。数据库启动时仅新增缺失字段。每次提交新增报告记录；学生可切换全部历史，老师展示每学生各阶段最新提交。

Git不会同步运行中的MySQL数据。本次将课程数据保存为可版本控制的`data/courses/compiler-2026.json`，启动后端时或运行`python scripts/seed_courses.py`时幂等同步课程码COMP2026及要求。固定ID避免重复；种子只更新仓库管理的课程，不改其他课程，不同步任何学生报告、回答、上传文件或密钥。该保留ID的课程内容以仓库种子为准。老师姓名显示“胡雯蔷”，管理账号绑定项目现有默认`teacher`，没有额外创建或替换人员账号。

其他电脑切换/拉取远程`test2`分支：

```powershell
git fetch origin
git switch test2
git pull --ff-only origin test2
conda activate voiceTA
python scripts/seed_courses.py
python scripts/run_dev.py
```

新电脑仍需按README准备MySQL和项目依赖，并在管理员配置中设置本机密钥（密钥不会通过Git分发）。`teacher / teacher123`登录老师端即可看到课程；学生在“加入课程”页面能看到课程名、老师与课程码，输入COMP2026加入后选阶段并上传材料。默认账号沿用项目原有开发配置。

## 验证与实际边界

离线：`python -m unittest discover -s tests -v`覆盖源码格式/编码、ZIP目录保留和二进制清单、路径穿越、重名/空文件、超长源码尾部、七阶段及选做计分、JSON失败、四类反思、最终加权与缺答拦截、种子幂等、API多文件提交和跨阶段历史保留。前端执行TypeScript检查与生产构建。

真实API：`python scripts/smoke_compiler_analysis.py --live`会调用计费模型，以明确标注为非学生的`.l + .c + Word`样例，确认三份材料被审查、识别手工自动机占位实现，生成具体问题并根据模拟回答输出分项评分；结果在本地`outputs/compiler-live-acceptance.json`，不写入学生数据库。课程列表与展开的详细要求已在本机浏览器验收。

本次没有用麦克风执行真人完整答辩，也没有验收ROS机器人硬件。既有系统仍使用前端localStorage角色和未加入服务端令牌校验的业务接口、开发默认密码；异步分析使用进程内BackgroundTasks，进程重启可能中断任务。这些是当前架构的既有边界，本次未将项目改造成生产多租户鉴权或持久化任务队列。公开部署前需要另行处理；课程和文件分析功能的本机测试并不能替代这些验证。
